# OFFICE LEASING Image Performance Guidelines

## 1. 목적

`officeleasing.co.kr`의 이미지 운영은 화질 경쟁보다 빠른 로딩, 안정적인 모바일 동작, 지도·목록·상세페이지의 체감 속도를 우선한다.

Smush Pro는 압축과 WebP/AVIF 변환을 담당하지만, 이미지 업로드 크기, WordPress 파생 이미지 크기, 템플릿 출력 방식, lazy load 정책을 함께 관리해야 한다.

## 2. 기본 원칙

- 확대 기능을 전제로 하지 않는다.
- 모바일에서는 이미지 확대·라이트박스를 제공하지 않는다.
- 메인페이지와 목록페이지는 데스크톱 4열, 모바일 2열을 기본으로 한다.
- 카드와 지도에서는 원본 이미지를 직접 출력하지 않는다.
- 실제 표시 크기보다 지나치게 큰 이미지를 전송하지 않는다.
- 화질은 육안상 충분한 수준으로 유지하되 속도를 우선한다.
- 첫 화면의 LCP 이미지를 제외한 이미지는 지연 로딩한다.
- Smush Pro, WP Rocket, 테마의 lazy load 기능을 중복 활성화하지 않는다.

## 3. 빌딩 외관 썸네일

빌딩 외관 이미지는 세로형 3:4 비율을 기본으로 한다.

### 권장 크기

- 기본 업로드 기준: `480 × 640px`
- 허용 최대 크기: `600 × 800px`
- 권장 파일 형식: WebP 또는 AVIF
- 목표 용량: `40~90KB`
- 최대 허용 용량: `120KB`

### 화면 사용

- 메인페이지 Building 카드
- For Lease 목록 카드
- 관련 Building 카드
- 모바일 2열 카드

모바일 카드의 실제 표시 폭은 약 160~190px 수준이므로 480px 폭 이미지는 충분한 해상도를 제공한다.

## 4. 내부 사진

### 권장 크기

- 기본 내부 사진: `600 × 400px`
- 대표 또는 넓게 표시되는 내부 사진: `900 × 600px`
- 권장 파일 형식: WebP 또는 AVIF

### 목표 용량

- 600 × 400px: `40~90KB`
- 900 × 600px: `70~140KB`

대부분의 내부 사진은 600 × 400px을 사용하고, 상세페이지에서 상대적으로 크게 노출되는 일부 대표 사진만 900 × 600px을 사용한다.

## 5. 지도 썸네일

- 권장 크기: `240 × 180px`
- 목표 용량: `30~50KB`
- 지도 정보창과 간단한 미리보기에서만 사용한다.
- 지도 팝업에서 원본 외관 사진이나 내부 갤러리 이미지를 호출하지 않는다.

## 6. Hero 이미지

Hero 이미지는 카드·갤러리 이미지와 별도 기준으로 관리한다.

Hero는 첫 화면의 핵심 시각 요소이므로 너무 작은 이미지를 사용하면 데스크톱에서 흐릿해질 수 있다. 다만 원본 그대로의 대용량 이미지를 전송하지 않는다.

### 권장 기준

- 데스크톱 기본: `1440 × 720px` 전후
- 큰 화면 대응 최대: `1600 × 800px`
- 모바일 전용: `750 × 900px` 또는 실제 모바일 Hero 비율에 맞춘 별도 이미지
- 목표 용량:
  - 데스크톱: `150~250KB`
  - 모바일: `90~160KB`
- 권장 형식: AVIF 우선, WebP 대체 제공

### Hero 로딩 규칙

- Hero는 lazy load를 적용하지 않는다.
- Hero가 LCP 이미지라면 `fetchpriority="high"` 또는 preload 적용을 검토한다.
- 데스크톱과 모바일에 동일한 대형 이미지를 강제로 사용하지 않는다.
- `<picture>` 또는 WordPress 반응형 이미지 기능으로 기기별 적절한 이미지를 제공한다.
- 한 페이지에서 여러 Hero 후보를 동시에 preload하지 않는다.
- 배경 이미지 CSS만으로 처리하여 `srcset`이 무력화되지 않도록 주의한다.

## 7. WordPress 이미지 크기 예시

```php
add_image_size( 'ol-building-thumb', 480, 640, true );
add_image_size( 'ol-map-thumb', 240, 180, true );
add_image_size( 'ol-interior', 600, 400, true );
add_image_size( 'ol-interior-large', 900, 600, true );
add_image_size( 'ol-hero-desktop', 1440, 720, true );
add_image_size( 'ol-hero-mobile', 750, 900, true );
```

실제 크기와 크롭 비율은 최종 Hero 디자인과 Building 카드 UI가 확정된 뒤 조정할 수 있다.

## 8. 템플릿 출력 규칙

- `wp_get_attachment_url()`로 원본 파일을 직접 출력하지 않는다.
- `wp_get_attachment_image()` 또는 프로젝트 이미지 Helper를 사용한다.
- 각 화면은 용도에 맞는 등록 이미지 크기를 명시한다.
- `srcset`, `sizes`, `width`, `height`가 정상 출력되는지 확인한다.
- 카드, 지도, 갤러리, Hero의 이미지 크기를 구분한다.

### 용도별 권장 호출

```text
메인·목록 Building 카드 → ol-building-thumb
지도 정보창 → ol-map-thumb
내부 갤러리 → ol-interior
넓은 내부 대표 이미지 → ol-interior-large
데스크톱 Hero → ol-hero-desktop
모바일 Hero → ol-hero-mobile
```

## 9. Smush Pro 역할

Smush Pro는 다음 역할에 집중한다.

- 업로드 원본 자동 축소
- WebP 또는 AVIF 생성
- 이미지 압축
- 불필요한 EXIF·메타데이터 제거
- 기존 이미지 일괄 최적화
- 잘못된 이미지 크기 감지

Smush Pro가 설치되어 있어도 템플릿에서 원본 이미지를 호출하면 성능 최적화 효과가 크게 줄어든다.

## 10. 모바일 정책

- 이미지 확대 기능 없음
- 라이트박스 없음
- 메인·목록페이지는 2열 카드
- 첫 화면 대표 이미지만 우선 로드
- 아래쪽 카드와 갤러리는 lazy load
- 보이지 않는 슬라이드 이미지를 초기 로딩하지 않음
- 모바일에서 데스크톱 Hero 원본을 그대로 전송하지 않음

## 11. 성능 완료 기준

이미지 기능은 다음 조건을 충족해야 완료로 본다.

- 메인·목록 카드에서 원본 이미지를 사용하지 않음
- 모바일 2열 카드에 과도한 해상도를 전송하지 않음
- Hero의 데스크톱·모바일 이미지가 분리 또는 반응형 제공됨
- Hero를 제외한 비핵심 이미지는 lazy load 적용
- Hero LCP 이미지에는 불필요한 lazy load가 적용되지 않음
- WebP 또는 AVIF 제공 확인
- `srcset`, `sizes`, `width`, `height` 출력 확인
- Smush Pro와 WP Rocket의 lazy load 중복 없음
- 지도 팝업은 전용 소형 썸네일 사용
- 실제 데이터가 쌓인 상태에서 모바일과 데스크톱 로딩 속도 확인

## 12. 운영 기준 요약

```text
빌딩 외관
- 기본 480 × 640px
- 최대 600 × 800px
- 120KB 이하

내부 사진
- 기본 600 × 400px
- 필요한 경우만 900 × 600px
- 140KB 이하

지도 썸네일
- 240 × 180px
- 30~50KB

Hero
- 데스크톱 1440 × 720px 전후
- 최대 1600 × 800px
- 모바일 전용 이미지 별도 제공
- 데스크톱 150~250KB
- 모바일 90~160KB
```

속도 저하 없이 충분한 화질을 유지하는 것이 OFFICE LEASING 이미지 운영의 기본 기준이다.
